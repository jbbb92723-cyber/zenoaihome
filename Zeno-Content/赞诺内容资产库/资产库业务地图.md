# 赞诺内容资产库业务地图

> 本文件只说明赞诺外层资产库如何协作。`内容结构化系统/` 仍严格遵循 dbskill 作者定义的内容工程规则，不因本文件改变目录、字段、关系或脚本。

## 1. 两套逻辑，各自负责一件事

资产库现在同时运行两套互补逻辑：

```text
内容结构化逻辑（dbskill）
原始素材
  → 来源登记
  → 内容单元（QST / CON / OPI / CAS / SOL）
  → 关系与去重
  → 主题地图
  → 选题装配

角色经营逻辑（赞诺）
角色
  → 阶段目标
  → 真实问题
  → 判断与技能
  → 所需知识
  → 实践动作
  → 结果证据
  → 可复用资产
  → 产品 / 服务
  → 市场反馈
  → 复盘升级
```

第一条回答「一份内容怎样被加工成可复用单元」；第二条回答「这份知识为什么值得加工、服务谁、如何被现实验证」。

不能把两条链合并成一套目录。正确关系是：

```text
角色经营逻辑决定方向和验收
            ↓
内容结构化系统负责加工和重组
            ↓
项目 / 服务 / 发布 / 星火者负责现实行动
            ↓
结果与反馈回到角色经营逻辑
```

## 2. 外层资产的职责地图

| 资产区 | 它是什么 | 当前入口 | 真正负责什么 | 不负责什么 |
|---|---|---|---|---|
| `_品牌定位/` | 身份与表达真源 | `_品牌定位/02_定位系统/` | 校准赞诺是谁、为谁服务、哪些事实可公开 | 不承载日常内容生产和项目过程 |
| `内容结构化系统/` | dbskill 内容加工引擎 | `内容结构化系统/SOURCE_OF_TRUTH.md` | 来源登记、内容单元、关系、主题地图和装配 | 不替代项目管理、发布状态或市场证据 |
| `_项目库/` | 真实实验与交付记录 | `_项目库/项目库/` | 记录一个项目的角色、目标、动作、结果、风险和复盘 | 不复制整篇内容单元或充当总内容库 |
| `_发布与产品/` | 市场输出与交付中台 | `_发布与产品/README.md` | 把已校准资产变成产品、服务、平台发布包和反馈记录 | 不作为身份真源，也不证明方法已经有效 |
| `星火者/` | 同伴实践与协作验证场 | `星火者/README.md` | 让角色进入行动、复盘、项目和可信协作 | 不等同资料群，不把成员资料自动公开 |
| `内容资产/OPC白皮书/` | 专题研究与长文交付包 | `内容资产/OPC白皮书/README.md` | 保存 OPC 专题原件、长文和对外交付版本 | 不把整本白皮书直接当作已验证方法 |
| `_搜索资产/` | 检索与分发元数据 | `_搜索资产/README.md` | 维护 SEO / GEO / 内链和搜索问题入口 | 不改写内容事实，不代替文章正本 |
| `_提示词与Agent/` | 执行工具层 | `_提示词与Agent/README.md` | 保存提示词、Agent 协作规则和工具入口 | 不把工具输出当作观点、证据或方法验证 |
| `perspective-skills/` | 外部视角参考层 | `perspective-skills/README.md` | 提供分析镜头和理论对照 | 不代表赞诺观点，不是当前业务真源 |

这里的「真源」指某类事实应在哪里修改；不代表其他目录不能引用它。

## 2.1 角色经营连接入口

角色经营逻辑不另建内容库，通过以下 4 个入口调用原有资产：

| 入口 | 职责 |
|---|---|
| `内容结构化系统/00-规则与索引/角色经营映射规则.md` | 定义角色层与内容单元、实践、证据的连接规则 |
| `内容结构化系统/03-处理状态/角色经营索引.csv` | 保存当前角色、阶段目标、调用资产、证据状态和唯一主动作 |
| `内容结构化系统/05-主题地图/赞诺角色经营总图.md` | 提供人读导航和角色调用顺序 |
| `内容结构化系统/04-产品服务/赞诺角色经营体系首轮30天实践.md` | 运行当前 30 天主实验并按结果验收 |

当前主实验只跑一条链：`OPC 公开实践者` → 装修签约前报价判断 → 1 次最小审核 → 一题多端 → 用户 / 星火者反馈 → 方法修订。在完成前不扩充角色数量，也不把角色知识体系包装成未经验证的新产品。

## 3. 一份资料怎样流动

### 输入层：先收事实，不急着写观点

输入可以来自：

- 赞诺亲历、工地和客户问题；
- 项目交付、失败、复盘和服务反馈；
- 星火者成员的实践记录（须先确认权限）；
- 平台评论、公众号追问、网站咨询和搜索问题；
- 外部账号、书籍、课程、政策和研究资料。

输入先保留来源、时间、作者、场景和权限。外部资料必须标为外部来源。

### 判断层：用角色经营画布筛选价值

每份准备继续加工的资料，先回答：

1. 服务哪个当前角色？
2. 这个角色本周期要完成什么结果？
3. 真实对象在什么场景遇到了什么问题？
4. 需要什么判断、技能或知识？
5. 这次要留下什么证据，证据不能证明什么？

不能回答前 3 项的资料，先留在原始资料或项目目录，不为了填框架强行抽取。

### 加工层：交给内容结构化系统

只有当资料进入内容加工边界时，才进入：

```text
内容结构化系统/01-原始素材区/
  → 03-处理状态/来源注册表.csv
  → 02-内容单元库/
  → 05-主题地图/
  → 06-选题装配/
```

这里的 `canonical: true` 只表示「内容单元当前主版本」，不表示它已经被市场验证、可教学或可产品化。

### 行动层：让资产接触现实

- 需要验证问题或方法：进入 `_项目库/` 或 `星火者/`；
- 需要形成服务、资料包或产品：进入 `_发布与产品/产品/`；
- 需要适配平台：进入 `_发布与产品/发布内容/`；
- 需要上线网站：以 `../../Zeno-Code/zeno-site/` 当前代码和数据为准；
- 需要搜索承接：在 `_搜索资产/` 补充入口和关系。

发布副本和产品文案都必须能回指内容单元、案例、项目或品牌真源；找不到来源的表达只能标为草稿或待补充。

### 回流层：反馈不是装饰，是下一轮输入

优先回收以下事实：

- 用户原话、误解和新增问题；
- 使用清单或工具时卡住的位置；
- 交付记录、采用情况、付费、拒绝和退款；
- 平台互动背后的具体语境，而不只是播放量；
- 项目结果、失败原因、协作信用和可脱敏案例。

反馈回到 `内容结构化系统/10_运行记录与复盘/` 或对应项目记录，再决定是否更新内容单元、方法卡、产品或品牌定位。

## 4. 证据状态与资产升级

西西笔记提供的可借鉴起点是：

```text
角色 → 目标 → 问题 → 技能 → 知识
```

其中「知识仓库 / 生产体系」的区分，以及事实性、程序性、概念性知识的区分，可以作为整理入口。它们属于外部启发，不能直接成为赞诺原创方法。

赞诺采用更长的验证链：

| 状态 | 依据 | 可以怎么用 |
|---|---|---|
| 外部启发 | 外部作者、理论或公开资料 | 研究、对照、注明来源 |
| 赞诺亲历 | 有真实经历，但原始记录不足 | 个人观察，不泛化 |
| 待验证 | 有判断或框架，尚无他人使用结果 | 实验假设和内部草稿 |
| 已有案例 | 有可回溯过程或结果 | 脱敏案例，说明样本边界 |
| 已验证 | 在明确场景中得到支持 | 阶段性方法，保留边界和反例 |
| 可教学 | 他人按步骤能复现关键动作或结果 | 课程、陪跑或社群交付 |
| 可产品化 | 有稳定需求、交付和付费证据 | 正式产品或服务 |

`canonical`、`当前有效`、`已验证`、`可产品化`是四个不同维度，不能互相替代。

## 5. 各类资产的处理规则

### 品牌定位

只保存身份、定位、表达、事实证据状态和视觉边界。新的内容观点应先进入内容结构化系统，不能因为写进品牌文件就自动成为品牌主张。

### 项目库

每个项目至少要能找到：角色、阶段目标、问题、最小行动、结果、证据、产生的资产、下一轮变量。项目文件是事实记录；成熟的可复用观点再回到内容单元库。

### 发布与产品

这里管理生命周期：草稿、待审核、待发布、已发布、反馈、归档。发布状态不等于方法验证状态；一篇文章发布了，只说明它被发布，不说明观点成立。

### 星火者

星火者是验证场。成员的原始内容默认只在授权范围内使用；经过脱敏和授权的结果，才能回流为案例、反例、方法边界或公开内容。

### OPC 白皮书

白皮书是专题包，内部可同时包含政策原文、外部研究、作者解读和交付排版。四者必须保持来源标签；需要进入长期知识底座的内容，单独抽取到内容结构化系统，不把整本 PDF 当成一个观点单元。

### 外部视角与工具

外部视角帮助提出问题，提示词和 Agent 帮助执行动作。两者都不能越过证据层直接升级为赞诺方法论。

## 6. 新资料的最短路由

```text
这是事实 / 原始记录？
  ├─ 是 → 放入对应原始资料、项目或星火者记录，并保留来源
  └─ 否
      ↓
这是外部研究或参考？
  ├─ 是 → 外部知识 / OPC 白皮书 / perspective-skills，标作者和证据状态
  └─ 否
      ↓
它是否围绕一个角色的真实问题产生？
  ├─ 否 → 暂存，不进入长期资产
  └─ 是 → 交给内容结构化系统加工
                 ↓
       形成内容单元 / 方法候选 / 项目实验 / 发布包
                 ↓
       回收结果与反馈，更新状态
```

以后新增文件不要求同时复制到多个目录。先确定一个真源，再用链接和索引连接其他用途。

## 7. 当前不做的事

- 不为了统一编号而改写 dbskill 标准目录。
- 不把外部账号的模型改名为赞诺原创。
- 不把发布稿、产品页、项目记录复制成多份内容单元。
- 不用播放量、点赞或文档完整度代替真实使用证据。
- 不在没有项目、成员授权或用户反馈时制造案例。
- 不以目录看起来整齐为理由移动或删除原始资料。
