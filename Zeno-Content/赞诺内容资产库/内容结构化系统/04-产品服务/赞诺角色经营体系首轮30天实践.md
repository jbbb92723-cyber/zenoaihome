# 赞诺角色经营体系首轮 30 天实践

## 本轮只验证一件事

> 角色经营知识体系能否把赞诺的一段真实行业经验，稳定加工成「可核验证据 + 可复用工具 + 多端内容 + 最小服务」，并获得至少一次真实用户使用反馈。

本轮不把涨粉、爆款、社群收入或成为行业 IP 设为验收目标。这些都是更长链路的结果，无法在没有基础证据时直接承诺。

## 当前角色

- **主角色**：传统行业经验资产化的 OPC 公开实践者。
- **垂直验证角色**：帮助装修业主在签约前看懂报价风险的判断顾问。
- **服务对象**：正准备装修、手里已有报价单，但看不懂责任边界的普通业主。
- **明确不做**：装修设计、材料测评、地区价格行情、泛 AI 教程、未经证实的创业成功教学。

## 30 天唯一关键结果

围绕一个真实报价问题完成一次闭环，并留下：

1. 3 份脱敏的真实问题或报价材料；
2. 1 次最小审核或判断工具试用；
3. 1 份经用户反馈修订的检查清单；
4. 同一问题的 1 条视频、1 篇公众号深文和 1 个网站证据页草稿；
5. 1 份公开复盘，说明哪里有效、哪里无效、尚不能证明什么。

## 待验证假设

| 假设 | 验证信号 | 证伪信号 |
|---|---|---|
| 业主真正缺的不是更多装修知识，而是签约前的判断顺序 | 用户能说出原来忽略的责任或风险问题 | 用户已有清晰判断，只缺价格或施工资源 |
| 赞诺的现场经验可以被加工成别人可使用的清单 | 用户不依赖赞诺解释，也能用清单发现问题 | 清单只有赞诺自己看得懂，用户无法执行 |
| 视频、公众号和网站可以围绕同一证据分工 | 三端内容各自承担注意、解释和信任，且能互相承接 | 三端只是重复发布，用户没有下一步行动 |
| 一次真实服务可以同时形成交付、内容和系统资产 | 至少产出一份工具、一组内容和一条方法修订 | 为了做内容干扰交付，或内容无法脱敏使用 |

## 四周节奏

### 第 1 周：收问题，不急着输出观点

- 从过去聊天记录、现有报价材料或真实访谈中收集 3 个签约前问题。
- 每个问题保存原话、发生场景、用户担心、已采取动作和材料位置。
- 选出一个高代价、能在 7 天内验证的问题。
- 建立本轮《赞诺角色经营画布》。

**周验收**：不是列出 20 个选题，而是获得 3 份可回溯输入，并确定一个真实问题。

### 第 2 周：做一次最小交付

- 用现有报价风险词库和判断框架完成一次脱敏审核或工具试用。
- 记录赞诺看了什么、如何判断、建议了什么。
- 请使用者复述「他原来怎么想、现在怎么判断、下一步会做什么」。
- 记录无效项、误解项和遗漏项，修订检查清单。

**周验收**：一份真实交付记录、一段原始反馈、一份 V1 检查清单。没有正向反馈也算完成，但必须保留失败原因。

### 第 3 周：一题多端，但各端不重复

| 渠道 | 内容任务 | 核心材料 |
|---|---|---|
| 平台视频 | 只讲一个反常识判断，引出真实问题 | 一个脱敏片段或风险词 |
| 公众号 | 解释问题为何发生、判断过程与适用边界 | 完整案例过程和方法 |
| 网站 | 展示赞诺是谁、证据是什么、如何工作、下一步怎么行动 | 身份、方法、脱敏证据、服务入口 |

三端都链接到同一个来源编号和资产记录，避免数据、经历和说法互相冲突。

**周验收**：完成一个一题多端内容包；至少一端真实发布，其余可为待发布稿。

### 第 4 周：让别人使用，再决定是否升级

- 邀请 1 位星火者或目标用户试用检查清单。
- 做一次 30 分钟复盘，收集「看不懂、做不到、不适用」的地方。
- 逐条判断 4 个待验证假设：支持、否定或证据不足。
- 把有效部分回写方法卡，把失败部分写进边界和反例。

**周验收**：一份同伴反馈、一份复盘、一张 V1.1 修改清单。

## 每周仪表盘

| 指标 | 目标 | 实际 | 证据位置 |
|---|---:|---:|---|
| 可回溯真实问题 | 3 |  |  |
| 完成最小实践 | 1 |  |  |
| 原始使用反馈 | 2 |  |  |
| 新增可复用资产 | 2 |  |  |
| 一题多端内容包 | 1 |  |  |
| 被否定或修订的假设 | 至少 1 |  |  |

「被否定或修订的假设」是必填项。四周后一个假设都没有变化，通常说明实验没有真正接触外部事实。

## 证据归档规则

- 客户或成员原话保留原始记录，对外使用前脱敏并授权。
- 机器转写必须标明模型和校订状态，不能写成官方字幕。
- 互动数据记录采集日期，不把点赞、收藏直接等同于方法有效。
- 每个结论同时写「能证明什么」与「不能证明什么」。
- 具体数字找不到来源时删除，不用估算补齐。

## 30 天结束后的决策

| 结果 | 下一步 |
|---|---|
| 用户能使用、反馈明确、资产可复用 | 升级为「已验证」，再做 3 个同类样本 |
| 问题真实，但工具不好用 | 保留问题，重做交付形式 |
| 内容有人看，但无人行动 | 检查证据、承接入口和目标对象是否匹配 |
| 用户不认为问题重要 | 放弃该问题，不用内容强行教育市场 |
| 只有赞诺自己觉得有价值 | 保持「待验证」，不进入课程和产品承诺 |
