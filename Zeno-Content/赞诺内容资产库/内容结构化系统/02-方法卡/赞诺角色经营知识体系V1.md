# 赞诺角色经营知识体系 V1

## 一句话定义

角色经营知识体系不是按学科收藏资料，而是围绕一个人正在承担的角色，把真实问题加工成能力、证据、资产和市场结果，再通过复盘持续升级。

```text
角色
→ 阶段目标
→ 真实问题
→ 关键判断与技能
→ 所需知识
→ 实践动作
→ 结果证据
→ 可复用资产
→ 产品或服务
→ 市场反馈
→ 复盘升级
```

## 它解决什么

普通知识体系回答「我知道什么」。角色经营知识体系必须继续回答：

1. 我现在以什么角色行动？
2. 这个角色在当前阶段要完成什么结果？
3. 哪个真实问题正在阻碍结果？
4. 我缺的是事实、方法、理解，还是实际练习？
5. 做完以后留下了什么可核验的证据？
6. 这次经验能否变成下次可复用的资产？
7. 市场是否愿意关注、信任、采用或付费？

知识没有进入动作和结果，只是输入；经验没有变成证据和资产，只是经历；资产没有接受市场反馈，还不能称为稳定方法论。

## 与外部「角色知识体系」的关系

`SRC-EXT-ACC-001` 提供了一个有价值的起点：从角色和目标逆推问题、技能与知识，并区分知识仓库和生产体系。

赞诺版增加五个经营环节：

| 外部起点 | 赞诺增加的环节 | 为什么必须增加 |
|---|---|---|
| 角色、目标、问题、技能、知识 | 实践动作 | 不行动，无法判断知识是否有效 |
| 知识服务技能 | 结果证据 | 不能只凭自我感觉宣布掌握 |
| 输出清单、模板 | 可复用资产 | 把一次经历变成下一次的生产资料 |
| 角色达成目标 | 产品与市场 | OPC 还要回答谁需要、为何采用或付费 |
| 个人生产体系 | 社群验证与迭代 | 用真实项目、他人使用和复盘检验边界 |

因此，外部内容是研究输入，不是赞诺方法论的所有权证明。赞诺方法论成立的依据，只能来自赞诺和星火者持续产生的实践记录、案例、使用结果与反例。

## 六层结构

### 1. 角色定位层

写清楚「我现在以什么身份，为谁解决什么问题」，不要用泛身份代替经营角色。

```text
泛身份：装修人、创业者、博主
经营角色：帮助装修业主在签约前看懂报价风险的判断顾问
```

最小字段：

- 当前角色
- 服务对象
- 典型场景
- 六个月目标
- 明确不做什么

### 2. 问题与技能层

先收真实问题，再决定学习什么。问题优先来自客户对话、项目阻塞、交付失误、搜索咨询和成员实践，不从课程目录倒推需求。

一个合格问题必须能定位到：

- 谁在什么场景遇到它
- 不解决会付出什么代价
- 当前做法为何无效
- 结果如何验收
- 需要哪些判断和动作

### 3. 知识与实践层

知识按用途处理：

| 知识类型 | 处理方式 | 例子 |
|---|---|---|
| 事实性知识 | 保留来源、日期和检索入口 | 法规、平台规则、产品参数 |
| 程序性知识 | 变成步骤、清单、模板或 SOP | 报价审核流程、访谈提纲 |
| 概念性知识 | 写清定义、机制、边界和反例 | 信任、判断力、职业自主权 |

每次学习必须绑定一个最小实践：回听一段对话、审核一份报价、发布一个判断、完成一次访谈、交付一个小工具或运行一次社群实验。

### 4. 证据与资产层

实践结束后至少留下两类产物：

- **结果证据**：用户原话、前后对比、交付记录、采用情况、付费记录、失败结果或反例。
- **可复用资产**：案例、判断规则、问题清单、模板、SOP、工具、逐字稿、文章或服务说明。

没有来源的具体数字、没有原始记录的小 A/B/C 案例、未经回听的机器逐字稿，不能作为已验证证据。

### 5. 产品与市场层

用市场反馈检验资产是否解决问题：

```text
公开一个判断
→ 有人停留、追问或转发
→ 有人使用清单或工具
→ 有人提交真实问题
→ 有人愿意付费获得更完整的判断或交付
→ 服务结果回流为新证据
```

对外系统分工：

| 系统 | 作用 | 回流到知识体系的信号 |
|---|---|---|
| 平台视频 | 分发一个清晰判断 | 停留、评论问题、转发语境 |
| 公众号 | 深耕一个主题 | 阅读反馈、收藏、长期追问 |
| 网站 | 用身份、证据、方法和结果建立信任 | 搜索进入、案例阅读、咨询行动 |
| 服务与产品 | 解决具体问题 | 采用、付费、交付结果和异议 |
| 星火者 | 行动、项目、复盘和协作验证 | 成员产物、复用结果、项目信用 |

### 6. 社群验证与迭代层

星火者不是资料分发群，而是角色经营知识体系的验证场。每位成员以自己的真实角色运行一个小闭环：

```text
角色说明
→ 本期真实问题
→ 7 天最小行动
→ 结果和证据
→ 形成一份资产
→ 同伴试用或项目检验
→ 复盘适用边界
```

## 证据状态

所有准备进入「赞诺方法论」的结论，至少标注一种状态：

| 状态 | 含义 | 可以怎么用 |
|---|---|---|
| 外部启发 | 来自他人的内容或理论 | 研究、对照，不用「我的方法」表述 |
| 赞诺亲历 | 赞诺真实经历过，但尚未整理证据 | 可讲个人观察，避免普遍化 |
| 已有案例 | 有可回溯的过程或结果记录 | 可作案例，说明样本边界 |
| 待验证 | 有逻辑但没有真实使用结果 | 只作假设或实验设计 |
| 已验证 | 在明确场景中得到一次或多次支持 | 可作阶段性方法，保留适用条件 |
| 可教学 | 他人按步骤使用后能复现关键结果 | 可进入课程、陪跑或社群交付 |
| 可产品化 | 有稳定需求、交付和付费证据 | 可进入正式产品或服务 |

状态升级必须补证据，不因文案写得完整而自动升级。

## 一次完整运行

### 第 1 步：选角色

本轮只选一个正在行动的角色。赞诺当前建议优先选择「OPC 公开实践者 / 传统行业经验资产化实践者」，装修判断顾问作为最具体的垂直验证场。

### 第 2 步：定阶段结果

目标写成 30 至 90 天内可检查的结果，不写「提升认知」「打造 IP」等无法验收的愿望。

### 第 3 步：收真实问题

建立问题收件箱。每条问题记录对象、场景、原话、代价和来源。每周只选一个高频、高代价、与角色目标有关的问题。

### 第 4 步：拆技能和知识

从完成结果需要的动作逆推关键技能，再判断缺哪类知识。能通过实践发现的，不先囤一整套课程。

### 第 5 步：做最小实践

限定在 7 天内产生外部可见结果，例如一次真实访谈、一份审核、一条公开视频、一页工具或一次成员试用。

### 第 6 步：收证据

保存原始输入、关键判断、采取动作、结果、用户反馈和失败点。事实与解释分开记录。

### 第 7 步：炼资产

用「一问三用」加工：

- 交付资产：问诊表、清单、SOP、工具。
- 内容资产：视频判断、公众号论证、网站证据页。
- 系统资产：方法卡、内容单元、提示词或 Skill。

### 第 8 步：过市场

观察的不是单一播放量，而是从注意、理解、信任、行动到付费的连续信号。没有行动信号时，检查问题是否真实、证据是否可信、表达是否清楚、入口是否明确。

### 第 9 步：做复盘

只回答五个问题：

1. 哪个假设被事实支持？
2. 哪个假设被否定？
3. 哪一步最耗时或最容易失真？
4. 哪份资产下次可以直接复用？
5. 下一轮只改变哪个变量？

## 赞诺当前角色地图

| 角色 | 当前目标 | 真实问题 | 优先资产 | 当前证据状态 |
|---|---|---|---|---|
| OPC 公开实践者 | 跑通经验资产化到服务验证的闭环 | 想法多，但真实案例与市场证据不足 | 周实践记录、服务实验、经营复盘 | 赞诺亲历 / 待验证 |
| 装修判断顾问 | 帮业主在签约前识别报价和预算风险 | 报价语言模糊、责任边界不清 | 风险词库、审核清单、脱敏案例 | 有部分资产，证据待补 |
| 内容型 IP 主理人 | 让内容持续建立可核验的信任 | 平台内容、公众号、网站之间缺少统一回流 | 一题多端、证据页、主题地图 | 已有系统，待运行验证 |
| 星火者发起人 | 让成员完成行动、资产和复盘 | 现有运营偏活动与内容，角色交付未完全嵌入 | 成员角色画布、周实验、资产台账 | 试运行 |
| 传统行业 AI 实践者 | 证明 AI 如何放大真实行业判断 | 容易滑向泛 AI 教学，缺少前后对比 | 工作流案例、时间与质量记录 | 赞诺亲历 / 待补证据 |

这张表不是永久身份清单。每季度根据真实投入、反馈和结果删除失效角色，避免知识体系无限膨胀。

## IP 如何由此长出来

IP 不是先设计一个人设，再持续找内容填充。赞诺的路径应是：

```text
持续解决同一类真实问题
→ 形成稳定判断
→ 用案例和工具证明判断
→ 在不同平台重复但分工明确地表达
→ 让受众能预期「遇到这类问题可以找赞诺」
→ 角色认知逐渐形成
```

判断一个内容是否服务 IP，只看四项：

- 是否强化一个清晰角色；
- 是否回应目标对象的真实问题；
- 是否展示赞诺独有的经历、判断或证据；
- 是否能引导到下一步行动或进入长期关系。

## 30 天最小落地

| 周次 | 行动 | 必须留下的资产 |
|---|---|---|
| 第 1 周 | 选定一个角色和 1 个高价值真实问题，完成 3 次访谈或材料回看 | 角色经营画布、问题清单、原始记录 |
| 第 2 周 | 做 1 次最小服务或工具试用 | 交付记录、使用反馈、失败点 |
| 第 3 周 | 将同一问题做成视频、公众号和网站证据页 | 一题多端内容包、来源链接 |
| 第 4 周 | 在星火者做一次复盘和同伴试用 | 复盘、同伴反馈、V1.1 修改项 |

30 天验收不是涨粉数，而是：是否完成一个真实问题闭环，是否留下至少一份证据和一份可复用资产，是否获得一次外部使用反馈。

## 使用边界

- 不因为收藏了某个模型，就将其改名为赞诺原创。
- 不用无法回溯的数字和虚构人物案例证明方法有效。
- 不把平台互动直接等同于客户需求或付费意愿。
- 不把一次成功推广为普遍规律。
- 不为填满框架而制造角色、问题或产品。
