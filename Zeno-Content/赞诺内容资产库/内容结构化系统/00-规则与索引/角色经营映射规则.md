# 角色经营映射规则

> 本文件是 `dbskill` 内容结构化系统与赞诺角色经营逻辑之间的连接规则。
> 它不新增内容单元类型，不替代 `02-内容单元库/`，也不把外部模型改写成赞诺原创。

## 1. 两层各自负责什么

`dbskill` 负责把一份材料加工成可复用的语义单元：

```text
原始来源 → QST / CON / OPI / CAS / SOL → 关系与去重 → 主题地图 → 选题装配
```

角色经营层负责决定这些单元为什么被调用、服务谁、如何验证：

```text
角色 → 阶段目标 → 真实问题 → 判断与技能 → 知识 → 实践 → 证据 → 资产 → 反馈
```

两层通过 `03-处理状态/角色经营索引.csv` 和 `05-主题地图/赞诺角色经营总图.md` 连接。

## 2. 为什么角色不写进内容单元类型

一条内容单元可能同时服务多个角色。例如「经验资产化」既服务 OPC 公开实践者，也服务传统行业 AI 实践者；如果复制成两份，版本、来源和去重都会失真。

因此：

- 内容单元只记录它是什么、来自哪里、回应什么和证明什么；
- 角色索引记录它被谁调用、用于哪个阶段目标和实践动作；
- 项目、服务、发布和星火者记录现实结果；
- 结果验证后再回写方法卡或内容单元，不在角色索引里制造第二份正文。

## 3. 角色索引字段

`角色经营索引.csv` 每行代表一个当前需要经营的角色，不代表永久身份。

| 字段 | 含义 | 规则 |
|---|---|---|
| `role_id` | 稳定的角色标识 | 使用 `ROLE-*`，不要用日期代替角色 |
| `stage_goal` | 本周期唯一可验收结果 | 30 至 90 天，不能写「打造 IP」 |
| `real_problem` | 当前真实问题 | 优先来自项目、服务、用户或成员原话 |
| `skill_actions` | 为达成结果要做的动作 | 写动作，不写抽象能力 |
| `knowledge_unit_ids` | 可调用的 QST / CON / OPI / CAS / SOL | 多个 ID 用分号分隔 |
| `method_card_paths` | 跨单元方法卡或模板 | 只写路径，不复制正文 |
| `practice_or_product_paths` | 实践、服务、发布或社群入口 | 必须能找到真实文件 |
| `evidence_status` | 当前证据等级 | 沿用外层证据状态，不等同 `canonical` |
| `next_action` | 当前唯一主动作 | 一次只保留一个主动作 |

## 4. 调用顺序

当用户按角色查询时，按以下顺序读取：

1. 先读本索引，确定角色、阶段目标和当前主动作；
2. 再读 `knowledge_unit_ids` 指向的内容单元，获取判断、边界和来源；
3. 再读方法卡或模板，形成可执行动作；
4. 到项目、服务、发布或星火者入口查结果证据；
5. 结果回到 `10_运行记录与复盘/` 或对应项目，再决定是否升级证据状态。

不能只根据角色索引摘要回答事实问题；索引只负责导航，原始文件和内容单元才是事实依据。

## 5. 证据纪律

- `canonical: true` 只表示内容单元当前主版本，不表示方法已验证。
- 外部来源只能标为「外部启发」，不能直接进入「赞诺方法论」的已验证层。
- 没有原始记录的数字、客户故事和结果，标为【待补充】，不填空。
- 一次发布、一次点赞或一次自我判断，都不能单独把方法升级为「已验证」。
- 角色索引只保留当前主路径；历史角色和失效路径放进运行复盘，不在这里堆积。

## 6. 当前运行焦点

2026-08-14 的主实验是：

> 以「OPC 公开实践者」为主角色，以「签约前报价判断」为垂直验证场，在 30 天内跑通一次真实问题 → 最小交付 → 证据 → 一题三用 → 反馈回填。

在该实验完成前，不新增课程承诺、不扩充角色数量，也不把角色知识体系包装成未经验证的新产品。
