# ZenoAIHome 网站架构说明

> 项目：`zenoaihome.com`
> 当前版本：V2.0｜2026-08-13
> 实际代码：`Zeno-Code/zeno-site/`

## 1. 网站定位

ZenoAIHome 是赞诺的个人品牌母站、公开实践档案和业务信任入口。

它首先解决信任问题：让第一次到访的人能核对赞诺是谁、正在做什么、使用什么判断、有哪些可见证据，以及下一步可以怎样行动。

**母定位**：

> 赞诺，一个从装修现场走出来的 OPC 实践者，正在公开验证如何用 AI，把传统行业经验变成可复用的判断、内容、工具和服务。

**网站与其他渠道的分工**：

| 渠道 | 任务 |
|---|---|
| 平台视频 | 分发一个清晰判断，让正在遇到问题的人看见 |
| 公众号 | 完整论证一个主题，建立长期阅读关系 |
| 网站 | 集中展示身份、证据、方法、案例、工具和行动入口 |
| 内容资产库 | 保存来源、组织角色知识、支持内容和交付生产 |

## 2. 网站不是什么

- 不是装修公司官网，也不是装修知识大全。
- 不是泛 AI 工具导航或技术教程站。
- 不是卖课落地页，不用赚钱、流量和成功承诺转化。
- 不是仅用来存放文章的无差别博客。
- 不直接把内部「角色经营知识体系」包装成新品牌。

## 3. 两类核心访客

### 装修业主

他们通常已有房子、方案、报价或合同，需要在签约和关键节点前看懂风险与责任边界。

主入口：装修判断工具、风险词典、检查清单、判断样张和装修顾问服务。

### 传统行业实践者

他们已有真实经验，但经验还散在人脑、聊天、文档和项目里，无法稳定表达、复用、协作或交付。

主入口：赞诺的 OPC 公开实践、经验资产化案例、AI 工作流、项目合作和星火者共同体。

两类访客共享赞诺的人格与方法，但必须进入不同的问题页、工具页和服务页，不在一个 CTA 中混合承接。

## 4. 首页任务

首页要在第一屏回答三件事：

1. 赞诺是从传统行业和装修现场走出来的 OPC 实践者。
2. 当前正在做的事，是用 AI 把真实经验变成可复用资产。
3. 访客可以阅读公开实践，或根据自己的问题进入装修判断与经验资产化两条路径。

首页信息顺序：

```text
人与母定位
→ 可核对的经验起点
→ 两条独立实践线
→ 经验资产化的工作过程
→ 公开内容与可见样本
→ 项目合作
→ 星火者验证共同体
```

## 5. 信任建立规则

网站不靠头衔墙建立信任，而是靠五类信息：

1. **身份**：统一的 17 年经验范围和当前实践角色。
2. **原始场景**：真实报价、项目、工作流和成员问题。
3. **判断过程**：看了什么，如何判断，哪些信息仍然不足。
4. **可用产物**：清单、案例、SOP、工具、工作流和交付样张。
5. **使用结果**：谁在什么边界内用过，结果和反例是什么。

未在《个人资料包》登记为可公开的数字、资质和头衔，不进入首页背书、About 资质标签、JSON-LD 和 `llms.txt`。

## 6. 内容主线

| 主线 | 回答的核心问题 |
|---|---|
| 传统行业经验资产化 | 散落的隐性经验怎样变成判断、案例、SOP、工具和服务 |
| OPC 一人公司 | 一个人如何组织产品、内容、交付、协作和现金流 |
| 装修判断 | 业主如何在签约和关键节点前看懂顺序、风险和责任 |
| AI 真实落地 | 知识库、工作流、智能体和网站如何进入具体任务并被验收 |
| 星火者实践 | 个人经验如何经过行动、试用、复盘和协作形成信用 |

## 7. 服务与共同体边界

- 装修业务线提供判断、风险识别和节点建议，不用无边界承诺取代设计、法务或监理职责。
- 经验资产化业务线从一个真实问题开始，先确认原始材料、交付物与验收边界，不直接承诺「打造 IP」。
- 星火者是小规模实践与协作验证场，不是资料群，不保证项目、收入、就业或投资结果。

## 8. SEO / GEO 方向

优先建立三组主题关联：

1. 赞诺 / Zeno / 陈国赞→传统行业经验资产化、OPC 一人公司实践。
2. 装修报价、合同、付款节点、预算→装修判断、工具与案例。
3. 传统行业 AI、知识库、工作流、智能体→有原始场景和验收边界的实践记录。

AI 可引用的事实必须能回到当前资料真源；`public/llms.txt` 只写已确认口径，不把旧文案改名为「Verified」。
