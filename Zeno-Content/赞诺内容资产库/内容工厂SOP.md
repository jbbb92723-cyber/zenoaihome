# 角色知识与内容资产 SOP

## 一、收到新资料

1. 确认来源：赞诺亲历、客户问题、项目记录、外部内容还是 AI 派生。
2. 判断资料服务的角色、目标和真实问题。
3. 原始资料存入 `内容结构化系统/01-原始素材区/`，不覆盖原文。
4. 外部内容注明作者、平台、链接、时间和采集边界。
5. 只有进入正式处理链的资料，才登记到 `内容结构化系统/03-处理状态/来源注册表.csv`。

## 二、建立角色链路

每次提炼前，先写清：

```text
角色：谁在使用这份知识？
目标：他想完成什么？
问题：现在卡在哪里？
技能：要解决它，需要会做什么？
知识：需要查什么事实、执行什么流程、理解什么概念？
证据：有什么案例、结果或来源能支撑？
```

无法回答前三项的资料，先保留在原始素材区，不急着抽成内容单元。

## 三、选择资产形态

| 资料的本质 | 沉淀形态 |
|---|---|
| 用户真正在问什么 | `QST` 问题单元 |
| 需要稳定理解的定义或模型 | `CON` 概念单元 |
| 赞诺经实践形成的判断 | `OPI` 观点单元 |
| 可核验的人、过程和结果 | `CAS` 案例单元 |
| 可执行的流程、清单、模板或工具 | `SOL` 方案单元 |
| 跨多个单元的系统技能 | 方法卡或主题地图 |
| 面向特定平台的完整表达 | 选题装配稿或发布稿 |

## 四、写内容

1. 从真实问题和具体场景开始。
2. 明确写出赞诺的判断，不用外部模型替代个人经验。
3. 补足证据：亲历细节、案例、原始来源、适用条件和反例。
4. 给读者一个可执行的下一步，不强制每篇内容销售产品。
5. 根据平台改变形式，不改变事实、核心判断和证据边界。

## 五、发布后

1. 记录发布链接、日期和平台。
2. 记录真实反馈：搜索、询单、评论、咨询、成交或无反应。
3. 只抽取真正可复用的新单元，不为了数量强行拆五张卡。
4. 把星火者成员的实践反馈，经授权和脱敏后回流为案例或方法边界。

## 六、每周维护

- 检查新来源是否有作者、链接和用途。
- 检查 `canonical: true` 的单元是否真正已核验。
- 检查方法是否有适用条件、反例和实践证据。
- 检查网站、公众号、视频和星火者是否产生了可回收的真实反馈。
- 删除无引用临时导出和错误派生物；有历史价值的旧版放归档。
