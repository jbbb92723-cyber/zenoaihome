# AGENTS.md｜赞诺内容资产库协作规则

> 本文件给 Codex、Claude、Hermes 以及其他 Agent 读取。它定义 `Zeno-Content/赞诺内容资产库/` 的边界、写入规则、内容结构化纪律和禁止事项。

## 1. 系统定位

这是 Zeno 的内容资产库，不是官网源码目录，也不是临时文稿堆。

它的目标是把 Zeno 的真实经验、观点、案例、概念、问题、方案和项目反馈，沉淀成可复用、可追溯、可重组、可继续生长的角色知识与内容资产系统。

这里可以服务官网、公众号、小红书、抖音、课程和咨询服务，但它本身不是任何单一平台的发布目录。

## 2. 与官网代码的边界

- 官网代码在 `../../Zeno-Code/zeno-site/`。
- 内容资产库不直接承载 Next.js 页面、组件、API 或构建配置。
- 除非任务明确要求，不要在处理内容资产库时修改网站代码。
- 除非任务明确要求，不要把网站代码文件迁入内容资产库。
- 内容资产可以为网站提供文章、案例、方法、服务表达，但需要经过整理后再进入 `../../Zeno-Code/zeno-site/data/` 或对应页面。

## 3. 当前核心模型

```text
OPC 公开实践
→ 经验资产化
→ 角色知识体系
→ 内容、工具、服务与产品
→ 星火者行动、验证与协作
→ 职业自主权
```

处理任何资料时，优先识别：

1. 谁是当前角色；
2. 角色要完成什么目标；
3. 当前真实问题是什么；
4. 需要什么技能和判断；
5. 需要哪类事实、程序或概念知识；
6. 有什么案例和结果能支撑。

## 4. 内容主轴

Zeno 的长期内容主轴包括：

- 居住与装修
- 美学与生活
- 人性与判断
- 成长与长期主义
- AI 与个体升级

处理素材时，先判断它属于哪条主轴，再判断是否值得进入长期资产。

## 5. 核心内容单元

内容结构化时，优先沉淀 5 类内容单元：

- `QST`：问题单元
- `CON`：概念单元
- `OPI`：观点单元
- `CAS`：案例单元
- `SOL`：方案单元

不要把长篇整稿直接当成内容单元。内容单元必须是可复用的最小语义对象。

## 6. 目录与局部规则

如果任务进入 `内容结构化系统/`，必须优先读取该目录下的：

- `AGENTS.md`
- `CLAUDE.md`
- `SOURCE_OF_TRUTH.md`

局部规则优先于本文件。

处理资料前先判断它属于：

- 原始素材
- 内容单元
- 主题地图
- 选题装配
- 发布稿
- 方法论
- 项目资料
- 归档资料
- 暂存资料

不要把所有内容都硬迁移到 ZenoAIHome 官网项目。

## 7. 默认写入规则

收到外部资料、截图、链接、灵感或旧文稿时，默认按以下顺序处理：

1. 判断资料价值：高 / 中 / 低 / 丢弃。
2. 判断归属层级：认知、内容、流量、商业、项目、方法、故事、暂存。
3. 高价值资料先进入收件箱或对应项目目录。
4. 可复用流程进入方法论或可调用方法库。
5. 和 ZenoAIHome 直接相关的装修、报价、签约、服务资料，进入对应项目资产路径。
6. OPC / AI 个体升级相关资料进入对应项目资产路径。
7. 重要写入后记录处理状态或运行复盘。

## 8. Obsidian 与链接规则

- 不移动 `.obsidian/` 配置。
- 正文引用其他内容单元、主题地图、选题装配时，优先使用 `[[文件名]]`。
- frontmatter 中的结构化 ID 保留 ID，不强行写成 Obsidian 链接。
- 批量补链前先审计，不要无差别替换正文。

## 9. AI 的角色

AI 可以做：

- 检索旧观点。
- 整理资料。
- 提炼机制。
- 抽取问题、概念、观点、案例、方案。
- 建立主题地图。
- 生成选题装配稿。
- 提出反方和新角度。
- 辅助标题、开头、结构检查。

AI 不应默认做：

- 一键生成重要逐字稿。
- 编造真实案例。
- 用模板化表达替代 Zeno 的表达审美。
- 把所有流程包装成狭义 AI workflow。
- 删除文件或大规模迁移，除非任务明确要求。

## 10. 内容原则

- 最终表达由人完成。
- 观点是 Zeno 的，AI 负责整理和辅助，不替代判断。
- 方法卡要短、清楚、可调用。
- 面向读者的文章要像人话，不要暴露内部工具语言。
- 可以多方法、多角度、多路径，但不要只剩一个万能模板。

### 10.1 下一步规则

每篇发布文章结尾应有与内容直接相关的下一步：继续阅读、使用工具、完成检查、补充证据、申请服务或了解共同体。不强制每篇文章销售产品。

使用模板：见 `内容结构化系统/07-模板库/TPL-20260710-001_文章CTA模板.md`

CTA 检查清单：
- [ ] 读者读完最后一个句号后，知道具体做什么？
- [ ] CTA 指向的目标页面真实存在？
- [ ] 下一步和读者当前角色、问题与阶段相符？
- [ ] CTA 与文章主题直接相关？

## 11. 星火者边界

- 星火者当前是小规模付费实践共同体，长期建设为 OPC 分布式协作网络。
- 读书会是输入机制，行动、经验资产、项目复盘和可信协作是核心交付。
- 共同体内容回流公开知识库前，必须脱敏并获得成员授权。
- 不承诺赚钱、客户、项目、就业或投资结果。

## 12. 文件安全

- 原始证据、已发布内容和当前真源默认保留。
- 有复盘价值的旧版优先放入所属目录的归档区。
- 经核验的完全重复、无引用临时导出、错误派生物可删除，并由 Git 保留历史。
- 不要改写原始素材副本。
- 不要移动 `.obsidian/` 配置文件。
- 不要修改网站代码目录，除非任务明确要求。
- 对外发布稿、内部方法卡、原始资料要分开存放。
- 大规模迁移、重命名、删除前必须先列清单并等确认。

## 13. 信息缺失规则

所有不确定、缺失、需要 Zeno 补充的信息，统一标记为【待补充】。

禁止用模糊表达、虚构细节或通用内容填补真实案例空白。
