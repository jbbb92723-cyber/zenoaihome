# 成熟团队联合交付协议框架

> 本文件用于广西赞诺数智科技有限公司与已经形成咨询、培训、FDE、产品或工程能力的成熟团队讨论项目合作。它不是可直接签署的正式合同，正式签署前必须由律师结合实际主体、客户合同、数据类型和税务安排复核。

## 1. 合作目标

双方不是为了签一份空泛的“战略合作协议”，而是建立项目级的联合交付机制：

- 广西赞诺数智科技有限公司负责企业入口、业务上下文、商务组织和项目责任。
- 成熟团队提供已经验证过的咨询、产品、工程、部署和质量能力。
- 每个客户项目单独签署 SOW，明确谁做什么、如何验收、如何结算、出了问题谁负责。
- 双方可以共同拓展能力，但任何既往案例、客户、团队数据和产品能力都必须按真实归属使用。

本框架不成立合伙企业、劳动关系、代理关系或共同品牌，除非双方在正式协议中另有明确约定。

## 2. 合作主体

甲方：**广西赞诺数智科技有限公司**

乙方：**[成熟团队实际签约公司全称]**

不得只以团队名、品牌名、个人微信或未登记的项目组作为收付款和责任主体。乙方如由多个公司或个人组成，应在每个项目开始前明确唯一责任主体及其授权人员。

## 3. 文件体系与优先顺序

每个项目至少包含：

1. 本联合交付框架协议。
2. 客户合同或客户订单。
3. 项目工作说明书（SOW）。
4. 报价与内部结算表。
5. 保密及数据处理附件。
6. 经双方确认的变更单。
7. 验收、交接和结算文件。

正式协议应写明文件冲突时的优先顺序。推荐原则是：经双方签署的最新变更单优先于原 SOW；SOW 优先于通用框架；客户合同中的外部义务只有在乙方事先收到并书面接受后，才作为乙方责任下传。

## 4. 三种项目合作模式

### 4.1 模式 A：甲方主合同 + 乙方分包（首期推荐）

- 甲方与客户签约、报价、收款和开票。
- 乙方与甲方签署分包 SOW，按工作包或里程碑交付并向甲方开票。
- 甲方是客户的统一责任入口，乙方接受项目治理和客户合同中已书面下传的相关义务。
- 适合客户来源于赞诺、需要统一商务界面、项目仍处于联合团队磨合期的情况。

优点是责任清晰；风险是甲方承担主合同、回款和总体交付压力。因此启动前必须完成成本、技术和责任复核。

### 4.2 模式 B：联合签约或三方合同

- 甲方、乙方与客户在同一合同中分别列明工作范围、价款、开票、验收和责任。
- 不使用“双方共同负责全部项目”这样的模糊表述。
- 适合双方能力都直接面对客户、采购方允许分项合同、责任可以清楚拆分的项目。

联合签约不等于默认共同收款或平均分配。每一方的金额、税费、付款条件和售后责任都应单列。

### 4.3 模式 C：乙方主合同 + 甲方业务与项目顾问

- 乙方与客户签约并承担主交付责任。
- 甲方按顾问、业务诊断、项目管理或渠道服务的明确工作包向乙方结算。
- 适合技术采购必须由乙方资质承接、或客户原本由乙方获取的项目。

此模式下仍需确认客户沟通权、赞诺对外身份、案例署名、售后参与和客户后续需求的处理方式。

每个项目只能选择一种主模式。模式变化必须书面确认，不能一边让甲方承担客户责任，一边把控制权和款项留在乙方。

## 5. 客户来源与商机登记

### 5.1 来源确认

客户首次进入实质沟通时，在项目台账登记：

- 客户全称、联系人和来源。
- 首次介绍人和介绍时间。
- 已知的双方既有关系。
- 当前机会、预计范围和下一步。
- 客户允许共享给对方的信息。

一方认为自己在介绍前已与该客户存在实质商业关系的，应在收到登记后 **5 个工作日** 内提供可核验记录；逾期未说明，不当然改变本次登记，但可由双方复核真实情况。

### 5.2 商务窗口

- 甲方来源项目，原则上由甲方统一报价和商务沟通。
- 乙方来源项目，按所选合作模式确定商务窗口。
- 技术和业务人员可以直接参加客户会议，但不得私下承诺价格、免费范围、交期和生产效果。
- 所有正式报价、折扣、赠送、回扣、渠道费和佣金必须经过双方授权人书面确认。

### 5.3 禁止绕单

在项目合作期及约定客户保护期内，任何一方不得绕开另一方，直接或通过关联方承接由对方引入且已登记的同一客户需求，也不得诱导客户拆分合同以规避应付结算。

正式协议应选择保护期，例如项目结束后 **[6 / 12] 个月**，并写清以下例外：公开招投标、引入前已经存在的业务、客户主动提出且经双方书面确认的新范围。建议首期采用 12 个月，但应由律师根据业务和竞争规则复核其合理性与可执行性。

禁止绕单不限制任何一方开展与本项目和受保护客户无关的正常业务。

## 6. 双方职责

### 6.1 甲方职责

- 承接或协助承接企业需求，核对客户背景和业务问题。
- 组织前期访谈、场景筛选、范围和价值判断。
- 维护客户沟通、会议纪要、决策记录、计划和变更。
- 根据所选模式完成合同、收款、开票或协调。
- 不未经授权把乙方案例、团队规模、客户数据和产品能力声明为甲方自有业绩。
- 按 SOW 提供客户资料、反馈和验收协调。

### 6.2 乙方职责

- 如实说明团队主体、人员、产品、案例、资质、第三方依赖和实际可投入资源。
- 在报价前完成技术可行性、工作量、风险和依赖评估。
- 按 SOW 配置人员，完成原型、开发、测试、部署、交接或质量复核。
- 遵守客户的数据、保密、安全、知识产权和现场管理要求。
- 对自己提供的代码、方案、人员资质和交付质量负责。
- 不未经授权绕开甲方向甲方来源客户报价、收款或承诺。

### 6.3 共同职责

- 在承诺客户前共同评审范围、资源、时间和风险。
- 区分既往案例与本项目结果，区分演示、验证和生产能力。
- 发现重大风险、延误或范围变化后 1 个工作日内通知对方。
- 不使用对方名称、Logo、联系人和项目资料进行超出授权的宣传。

## 7. 项目治理

每个 SOW 必须指定：

- 商务负责人。
- FDE Lead / 项目负责人。
- 业务负责人。
- 技术负责人。
- 质量与安全复核人。
- 双方变更授权人。
- 客户验收人。

项目采用一个计划、一套决策记录和一个正式文档库。微信、电话和现场口头决定应在 1 个工作日内回写；未回写确认的内容不得用于证明已经同意增加范围。

推荐会议节奏：

- 启动会：确认目标、范围、角色、数据和风险。
- 项目例会：同步完成证据、计划偏差和阻塞。
- 里程碑评审：按 SOW 决定通过、修正、暂停或变更。
- 验收与复盘：完成客户签收、内部结算和经验回写。

## 8. 报价、成本与结算

### 8.1 对客报价

对客价格应由工作范围、预计人日、外部成本、税费、风险、项目管理、售后和合理利润构成。乙方在甲方报价前提供可核验的内部工作量和分包报价。

禁止先用低价获取客户，再默认要求另一方无偿补足范围。

### 8.2 内部结算方式

每个项目选择一种方式并写入 SOW：

- 固定工作包价。
- 人日单价与封顶金额。
- 里程碑固定价。
- 经双方明确计算口径的项目分成。

首期推荐固定工作包或里程碑价。不设置“联合团队默认五五分”“星火者统一管理费”或没有成本依据的永久分润比例。

### 8.3 付款与回款风险

SOW 应明确：

- 含税或不含税价格、税率和开票主体。
- 客户付款节点与乙方结算节点。
- 首付款到账前是否启动。
- 客户迟延付款时双方如何处理。
- 退款、扣款、返工和坏账由谁承担。

是否采用“收到客户对应里程碑款后再向乙方付款”的背靠背安排，必须在项目开始前明确。没有明确约定时，不得事后把一方的客户回款风险全部转移给另一方。

### 8.4 变更

任何范围、时间、人员、接口、部署和验收变化都应形成变更单，写清增加或减少的价款、人日、排期和责任。未确认变更前，双方有权继续按原 SOW 执行。

## 9. 数据、保密与安全

- 双方只为项目目的处理必要数据，不把客户资料用于训练、营销或其他项目。
- 数据进入任何大模型、云服务、标注平台、代码仓库或第三方工具前，必须确认客户授权和服务条款。
- SOW 或数据附件应列明数据类别、敏感级别、存储区域、访问人员、保留时间和删除方式。
- 使用脱敏或合成数据能完成验证时，不使用真实敏感数据。
- 发生误发、越权、泄露、账号被盗或重大漏洞时，发现方立即采取止损措施并通知另一方，按正式协议和适用法律处理。
- 项目人员退出时立即撤销权限并完成资料交接。

双方对在合作中获得的客户信息、报价、代码、方案、人员信息和未公开业务承担保密责任。保密期限和法定例外在正式协议中确定。

## 10. 知识产权

### 10.1 背景知识产权

各方在项目开始前已经拥有的代码、模型、模板、课程、方法、商标、数据和工具归原权利人。使用对方背景资产时，应在 SOW 中说明授权范围、期限、地域、费用和能否转授权客户。

### 10.2 项目成果

项目定制成果的归属应与客户合同一致，并在甲乙双方 SOW 中同步。不得出现甲方已经向客户转让全部权利，而乙方仍保留冲突权利的情况。

### 10.3 通用组件

乙方或甲方在项目中使用的通用组件、底层框架和不含客户保密信息的既有能力，可保留所有权；客户和另一方获得何种使用许可需明确。不能用“通用能力”名义带走客户数据和定制业务规则。

### 10.4 第三方与开源

使用模型、API、SaaS、开源代码、字体、数据集和素材时，应记录许可证、费用、商用限制、数据政策和持续可用风险。任何一方不得引入会使客户成果承担未披露开源义务或侵权风险的资产。

## 11. 案例、品牌与对外披露

- 使用客户名称、Logo、截图、数据和结果前，必须取得客户书面授权。
- 使用对方案例和成员履历前，必须确认来源、本人贡献、可公开范围和有效期。
- 联合案例应分别说明客户来源、商务责任、实际交付方和各自贡献，不把合作成果全部归于单方。
- 未经书面授权，不得以“战略伙伴、联合公司、官方指定、独家团队”等身份对外宣传。
- 星火者成员参与项目时，对外身份按项目文件确认；会员身份本身不构成项目资历。

## 12. 验收、质保与售后

每个 SOW 应定义：

- 交付物、版本、环境和验收样本。
- 功能、性能、安全和文档标准。
- 验收反馈期限及逾期处理方式。
- 缺陷等级、修复时限和不属于缺陷的变更。
- 免费质保期限和质保范围。
- 质保后的运维、模型/API 费用和服务等级。

因客户环境、第三方服务、模型变更、未经授权修改或超范围使用造成的问题，不应自动认定为乙方交付缺陷，但团队应提供必要的诊断证据。

## 13. 人员、分包与星火者参与

- 核心人员更换需提前通知，并确保能力、交接和权限处理不降低项目质量。
- 未经对方和客户必要授权，不得再次把关键工作整体分包给未知第三方。
- 星火者可以作为候选人才来源，但进入项目后必须以个人、个体工商户或公司等合法主体另签工作单或协议。
- 星火者会员费不抵项目费用，会员身份不保证项目、收入、优先派单或默认分润。
- 任何项目成员都应完成保密、知识产权、报酬、税务、退出和成果交接确认。

## 14. 责任、暂停与终止

正式协议应结合合同金额、可预见损失、数据类型和保险情况约定责任范围及上限，不在本讨论稿中虚构统一比例。

出现以下情况时，一方可以要求暂停：

- 客户或另一方未提供必要资料、权限、付款或人员。
- 数据来源或授权存在重大疑问。
- 需求变化使原范围、成本或时间基础失效。
- 发现重大安全、侵权、违法或商业贿赂风险。
- 继续执行可能明显扩大损失。

严重泄密、欺诈、绕单、冒用品牌、长期不履约或拒绝修复重大违约时，可以按正式协议终止。终止时仍应完成：

- 已完成工作和应付款项确认。
- 数据、账号、代码、文档和设备返还或删除。
- 在制成果、决策和风险交接。
- 客户连续服务安排。
- 继续有效的保密、知识产权和禁止绕单义务。

## 15. 争议处理

争议先由项目负责人在 2 个工作日内整理事实、合同条款、证据和影响；无法解决时升级至双方授权代表。正式协议应选择适用法律、管辖法院或仲裁机构，并由律师确认。

争议期间，对无争议的交付、数据保护和客户连续性义务应继续履行；存在安全或违法风险的部分除外。

## 16. 项目 SOW 最小字段

| 类别 | 必填内容 |
|---|---|
| 项目信息 | 客户、来源、合作模式、项目名称、背景 |
| 目标范围 | 目标、非目标、交付物、排除项 |
| 角色责任 | 双方负责人、成员、RACI、客户验收人 |
| 计划 | 里程碑、依赖、会议、文档和变更机制 |
| 数据安全 | 数据类别、权限、第三方服务、留存和删除 |
| 技术 | 架构、环境、接口、模型、开源和部署 |
| 验收售后 | 样本、指标、反馈期限、缺陷、质保和运维 |
| 商务结算 | 对客价、内部分包价、税费、付款和坏账安排 |
| 知识产权 | 背景资产、定制成果、通用组件和客户授权 |
| 对外披露 | 案例、Logo、署名、数据和联系方式授权 |
| 风险退出 | 暂停、替换、违约、终止和连续性交接 |

## 17. 首次签约前核对清单

- [ ] 乙方实际签约主体、开票能力和授权人已核验。
- [ ] 双方既往案例和团队数据的使用权限已确认。
- [ ] 首个项目选择了唯一合作模式。
- [ ] 客户来源、商务窗口和保护期已登记。
- [ ] 客户合同义务已经逐项下传并被乙方接受。
- [ ] SOW 的范围、人日、排除项、里程碑和验收明确。
- [ ] 对客价格、内部结算、税费和回款风险明确。
- [ ] 数据、模型、开源、知识产权和案例授权明确。
- [ ] 核心人员、备份人、权限和退出交接明确。
- [ ] 律师已复核合同主体、责任限制、数据条款和争议解决。

---

本框架的核心不是把关系写得亲密，而是让每个项目在客户来源、责任、钱、数据、成果和退出上都能说清楚。未进入具体 SOW 的合作意向，不应对外宣传为已经具备的交付事实。
