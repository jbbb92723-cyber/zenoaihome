# 我的装修档案：部署门槛

“我的装修档案”默认由 `RENOVATION_ARCHIVE_ENABLED=false` 关闭。以下条件全部完成前，不得在生产环境开启。

## 1. 数据库

当前仓库的 Prisma migration 历史不是完整 baseline，不能直接在生产运行 `prisma db push`，也不能未经核对直接执行全量 `migrate deploy`。

上线顺序：

1. 对生产数据库做只读 schema 对账，确认已有表、索引、外键和 Prisma migration 记录。
2. 基于生产现状生成装修档案增量 migration，先在 staging 执行。
3. 在 staging 演练创建档案、上传、确认、删除和 Cron 清理。
4. 生产备份后执行已经演练的增量 migration。
5. migration 成功后再部署代码，功能开关仍保持关闭。

本功能需要的模型是：`RenovationArchive`、`ArchiveAsset`、`QuoteVersion`、`QuoteItem`、`QuoteItemRevision`，并包含材料声明、延迟删除和 Zeno 审核字段。最终 migration 必须以当时的 `prisma/schema.prisma` 为准生成，不能手写猜测生产结构。

## 2. Supabase Storage

创建 `renovation-archives` bucket，并逐项确认：

- `public = false`
- `file_size_limit <= 10485760`（10MB）
- `allowed_mime_types` 恰好为 `text/csv` 和 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- `SUPABASE_SERVICE_ROLE_KEY` 只存在于服务端环境变量
- `RENOVATION_ARCHIVE_UPLOAD_SECRET` 是独立随机密钥，至少 32 字符

代码会在签发上传地址前通过 Storage API 复核这些设置；不符合时拒绝上传。

如果将来更换 bucket，旧 bucket 名必须先加入 `SUPABASE_RENOVATION_ARCHIVE_ALLOWED_BUCKETS`，直到旧文件全部清理完毕，避免数据库墓碑删除后旧对象遗留。

## 3. 审核身份与清理任务

- 设置至少 32 字符的 `CRON_SECRET`，确认 Vercel Cron 能携带对应 Bearer 凭证访问 `/api/cron/renovation-archive-cleanup`。
- 将 Zeno 的 Auth.js 用户设为 `ADMIN`，并配置 `ZENO_REVIEWER_USER_ID`。邮箱只作为临时兜底。
- “Zeno 本人已审核”只能在客户确认并锁定版本后写入；写入会记录审核人、时间和 `AdminLog`。
- 删除申请会立即从客户账号隐藏，原文件先尝试删除；数据库记录在上传签名安全窗口结束后由 Cron 最终删除。每日 Cron 下，实际完成时间可能约为 3 至 27 小时，失败时继续保留墓碑并重试。
- `RENOVATION_ARCHIVE_ENABLED` 只控制客户入口，不控制后台清理。即使紧急关闭功能，Cron 仍必须继续运行，直到已有上传预留和删除墓碑全部处理完毕。
- 未完成上传按单文件上限 10MB 预占额度；只有 Storage 元数据核验通过并建立版本后，才改按实际文件大小计入。不要为了提高并发上传数而放宽这条约束。

## 4. 开启前验收

开启 staging 功能开关后，至少验证：

1. 非登录用户、跨账号用户无法读取档案或文件。
2. 超过 10MB、非 CSV/XLSX、错误 MIME 的上传被拒绝。
3. 上传票据响应丢失后，以同一客户端幂等键重试会复用原预留；同一键换文件信息会被拒绝。
4. 未完成文件按 10MB 预占：已有 45MB 已核验文件时，即使新请求声称只有 1 字节，也不能再签发上传地址。
5. 报价版本响应丢失后，即使业务上传凭证已经过期，完全相同的请求仍可读取已建立版本；同一凭证更换名称或条目会被拒绝。
6. 客户确认和 Zeno 审核的首次请求、重复请求返回相同 JSON 结构。
7. 并发执行档案更新与删除时，删除状态不能被更新请求恢复。
8. Cron 在功能关闭时仍执行；单条 Storage 失败不阻断同批其他目标，失败目标轮转后不会长期饿死后续删除请求，并发 Cron 不重复删除同一目标。
9. 使用真实 staging bucket 验证官方 multipart 签名上传、HEAD 返回的文件大小/MIME，以及 DELETE；不能只用 TypeScript 或构建结果代替这项契约测试。
10. 自动提取、客户修正、客户确认、Zeno 本人审核四种责任状态与实际操作一致。
11. Storage 删除失败时数据库墓碑仍保留，下一次 Cron 可以继续清理。
12. 功能关闭时账号、工具、助手、页面和 API 均不暴露入口；助手正文、列表和追问也不能残留档案 URL。

验收完成后，先小范围开启并观察 Storage、数据库连接、Cron 失败数和服务点击事件，再决定是否扩大开放。
