# 文章互动与 IP 反馈系统方案

> 版本：v1.0 · 2026-08-16

## 1. 先定原则

文章页不需要复制内容平台的全部功能。评论、点赞和分享只有在能改善读者获得感、帮助 Zeno 判断内容方向或推动真实服务交付时，才值得存在。

因此网站不把互动设计成“谁热度高”的排行榜，而是设计成一条反馈链：

```text
读者阅读 → 标记有帮助 / 分享 / 留下具体问题
        → 人工审核与归类
        → 选题、文章、工具和服务边界调整
        → 真实客户交付验证
        → 把验证后的方法补回内容和 SOP
```

互动数据是判断材料，不是商业闭环证据。只有真实客户输入、实际交付、客户反馈和可复用 SOP 逐层成立，才可以称为服务验证。

## 2. 第一版功能边界

### 保留

| 功能 | 访问门槛 | 作用 | 前台展示 |
|---|---|---|---|
| 分享 | 无登录 | 让判断离开本站，记录读者愿意转发什么 | 显示分享按钮，不显示分享排行榜 |
| 对我有帮助 | 无登录 | 收集低摩擦的“这对我有用”信号 | 显示总数，但不做热度叙事 |
| 评论 | 登录后 | 收集具体问题、反例和追问 | 只显示审核通过的评论 |
| 评论审核 | 管理员 | 控制噪音、隐私和风险 | 不对读者暴露审核细节 |

### 暂不做

- 公开点赞榜、关注人数、热度排序和“爆款”标签；
- 匿名评论、无限楼中楼、私信式客服；
- 自动 AI 回复评论；AI 可以辅助归类，不能替 Zeno 对外承担判断；
- 强制登录阅读、弹窗订阅和“点赞后才能继续”；
- 把一次互动直接当成客户需求、案例或商业证据。

这能避免页面出现“此地无银三百两”的解释性话术：网站公开价值本身，互动只是帮助判断读者是否真的用上了它。

## 3. 技术设计

### 数据模型

- `ArticleReaction`：记录 `articleSlug + kind + visitorId`，第一版只有 `helpful`；访客 cookie 去重，可关联登录用户但不依赖登录。
- `Comment`：记录文章、用户、正文、审核状态、审核人、审核备注和时间。
- `AnalyticsEvent`：记录分享事件和分享方式，不把分享次数混进“帮助”统计。

### API

```text
GET  /api/articles/:slug/engagement
POST /api/articles/:slug/engagement { kind: helpful | share, method? }
GET  /api/comments?slug=:slug
POST /api/comments { articleSlug, content }
GET  /api/admin/comments?status=:status
PATCH /api/admin/comments { id, status, moderationNote? }
```

所有文章 slug 都先经过文章注册表校验。评论 POST 需要 Auth.js 会话，并按用户和文章做限流；评论 GET 只返回 `approved`。管理员接口使用现有 `ADMIN / OPERATOR` 角色和旧后台 cookie 迁移兜底，审核动作写入 `AdminLog`。

### 降级原则

互动 API 或数据库短暂不可用时，文章正文仍然必须可读。互动组件隐藏失效统计并提示“互动暂时不可用”，不能把数据库错误伪装成真实的 0。

## 4. 评论审核 SOP

1. 每天或每次收到提醒后，先看“待审核”。
2. 通过：内容具体、与文章相关、没有泄露他人隐私或明显导流。
3. 拒绝：空泛灌水、与文章无关、明显广告或把评论区当客服入口。
4. 垃圾：批量重复、恶意链接、攻击或机器生成的无意义内容。
5. 通过的评论只作为公开讨论；有代表性的问题另行摘录到选题池，保留原始问题和来源文章。
6. 只有完成真实交付并获得客户反馈后，才把问题升级为案例、SOP 或商业证据。

## 5. 反馈如何回流

后台每周只看三类信号：

- **获得感信号**：哪些文章被标记“有帮助”或被分享；
- **困惑信号**：读者反复追问的概念、步骤或边界；
- **行动信号**：读完后进入工具、服务说明、申请或真实交付的路径。

判断顺序应是：先回到原文和读者语境，再决定是否补文章、做工具、改 SOP 或调整服务边界。不要因为一篇文章互动多，就自动扩大服务范围。

推荐的人工记录字段：

```text
来源文章 | 读者原问题 | 问题类型 | 当前已有答案 | 缺失证据
是否值得写 | 是否值得做工具 | 是否进入真实交付 | 后续结果
```

这张表比“点赞数”更接近 IP 的判断资产。

## 6. 第二阶段候选能力

只有第一版运行一段时间并能稳定处理反馈后，再考虑：

- 收藏与阅读历史：服务于读者长期使用，不服务于留存报表；
- 主题订阅：按读者真正关心的判断主题发送更新；
- 评论问题库：人工确认后，把问题与文章、工具、服务建立关联；
- 文章数据看板：帮助数、分享方式、评论主题、后续行动分开看；
- 评论回复：由 Zeno 本人或明确身份的人回复，保留人工责任边界。

暂不引入无限互动、社区等级和复杂推荐算法。网站的核心资产仍然是可验证的判断、交付过程和持续修正后的 SOP。

## 7. 第一版验收标准

- 未登录读者可以正常阅读、分享和标记有帮助；
- 登录用户可以提交评论，提交后默认待审核；
- 前台只显示审核通过的评论；
- 管理员可以筛选并审核评论，操作写入日志；
- 数据库或互动 API 出错时，正文不受影响；
- 互动数据不被文案包装成客户数量、交付案例或商业证明；
- 每周至少人工处理一次反馈，并能说清一条反馈最终进入了什么内容或 SOP。
